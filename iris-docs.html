NaN-boxing: Všechny hodnoty jsou 8 B (Value). Int, bool, null a SSO string se ukládají přímo do value. Double, heap string, object, array a native pointer se ukládají jako pointer se speciální NaN-signaturou.

Řídicí struktury

Podmínky (if/else)

if (x > 0) {
    print("kladné")
} else if (x < 0) {
    print("záporné")
} else {
    print("nula")
}

Cykly

// while
while (x < 10) {
    x = x + 1
}

// for (C-style)
for (var i = 0; i < n; i = i + 1) {
    print(i)
}

// for-in-range (start..end)
for i in 0..n {
    print(i)
}

// repeat (pevný počet)
repeat (5) {
    print("Ahoj")
}

// break / continue
while (true) {
    if (done) break
    if (skip) continue
}

Switch

switch (x) {
    case 1 { print("jedna") }
    case 2 { print("dva"); break }
    default { print("jinak") }
}

Switch lze použít i jako výraz (vrací hodnotu z case/default).

Funkce

Deklarace

fun add(a: int, b: int): int {
    return a + b
}

// bez návratového typu (vrací null)
fun greet(name: string) {
    print("Ahoj " + name)
}

// tail-call optimalizace
fun fact(n: int, acc: int): int {
    if (n <= 1) return acc
    return fact(n - 1, acc * n)  // tail call
}

Základní třída

    var name: string
    var age: int

    Person(name: string, age: int) {
        this.name = name
        this.age = age

        print("Jsem " + this.name)

Dědičnost

class Student : Person {
    var school: string

    Student(name: string, age: int, school: string) {
        super.Person(name, age)
        this.school = school
    }

    override fun greet() {
        super.greet()
        print(" — student na " + school)
    }
}

Základní operace

// Interpolace

print("Ahoj $name")             // Ahoj Anna
print("2 + 3 = ${2 + 3}")       // 2 + 3 = 5

Bytecode VM & JIT

Virtuální stroj

  • Register-based VM s 256 registry na frame
  • NaN-boxed hodnoty (vše 8 B Value)
  • 105 definovaných opcode
  • Flat call stack s register windowing
  • Garbage collector: mark-and-sweep (trigger po 256 operacích v cyklech)
  • Peephole optimalizace bytecodu

JIT kompilace

  • Dvě úrovně JIT: function-level (method stuby) a trace-based (hot loop detection)
  • Function-level JIT kompiluje celou funkci do nativního x86-64 kódu při prvním zavolání
  • Trace JIT detekuje hot loopy a kompiluje je do nativního kódu s dynamickým unrollingem (2-8x)
  • Používá Asmjit knihovnu pro generování strojového kódu
  • Polymorphic inline cache pro dynamický method dispatch
  • SIMD optimalizace (arraySum)
  • Escape analýza: alokace na zásobníku pro neescapující objekty

Mapování registrů (x86-64)

VM registrx86-64Calling convention
v[0]r13callee-saved
v[1]r14callee-saved
v[2]r15callee-saved
v[3]rbpcallee-saved
v[4]rbxcallee-saved

Registry r8–r11 (v[5]–v[8]) jsou caller-saved podle Win64 ABI. Před každým voláním C helperu jsou uloženy do paměti (flushRegs) a po návratu obnoveny (reloadVRegs).

ProměnnáVýznam
IRIS_NO_JITPokud je nastavena, JIT kompilace je zcela vypnuta. Vše běží v interpretru. Užitečné pro debugování nebo při nestabilitě JIT.
IRIS_TRACEPokud je nastavena, každá vykonaná instrukce je vypsána na stderr. Pouze v interpretru.

Základní opravy JIT (2026-07)

Byly opraveny všechny známé kategorie chyb v registrovém mapování:

  • Cat. 1: r11 (v[8]) používán jako scratch v INT-only aritmetice → nahrazen rax/rcx
  • Cat. 2: r11 (v[8]) používán pro typ-tag extrakci v double aritmetice → nahrazen rcx
  • Cat. 3: Chybějící reload po flushRegs+call ve funkcích (OP_NEW_ARRAY, OP_COLL_LEN, OP_LOG, OP_WAIT, OP_PUSH/POP_HANDLER) → doplněno
  • Cat. 4: Chybějící flushRegs v C helper slow path (arithmetické a porovnávací operace) → doplněno
  • Cat. 5: OP_DIV_K používal r8d místo ecx → opraveno
  • Trace JIT: reloadVRegs doplněn do všech helper call sites
  • Side exit: Dead store eliminace v trampoline

Všechny tyto opravy jsou pokryty testy v tests/scripts/jit_stress_*.iris.
